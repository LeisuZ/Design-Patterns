# 电商购物车系统设计模式应用报告

## 摘要

本报告详细阐述了电商购物车系统中11种设计模式的应用情况。本项目以电商购物车结算模块为载体，深入展示了创建型模式（单例、工厂、抽象工厂）、结构型模式（适配器、装饰器、外观）和行为型模式（策略、职责链、观察者、命令、模板方法、状态）在实际项目中的应用。报告重点分析了每种模式的设计意图、实现方式、业务场景应用以及模式之间的协作关系。

---

## 一、项目背景

### 1.1 项目概述

本项目是一个基于Java Swing的电商购物车结算模块，实现了完整的电商购物流程，包括商品管理、购物车管理、订单处理、支付、物流跟踪、会员系统和评价系统等核心功能。

### 1.2 设计目标

1. **高内聚低耦合**：通过设计模式降低模块间的耦合度
2. **可扩展性**：支持新功能的无缝扩展
3. **可维护性**：代码结构清晰，易于理解和维护
4. **设计模式实践**：将设计模式理论应用于实际项目

## 三、创建型模式详解

### 3.1 单例模式（Singleton Pattern）

#### 3.1.1 设计意图
确保一个类只有一个实例，并提供一个全局访问点。

#### 3.1.2 实现方式
本项目采用**枚举实现**，这是实现单例模式的最佳实践：
- 线程安全：枚举实例由JVM保证只创建一次
- 防止反射攻击：枚举类型无法通过反射创建实例
- 防止序列化破坏：枚举天然支持序列化

#### 3.1.3 应用实例

**Logger（日志记录器）**
```java
public enum Logger {
    INSTANCE;
    private PrintWriter writer;
    
    private Logger() {
        try {
            writer = new PrintWriter(new FileWriter("app.log", true));
        } catch (IOException e) {
            e.printStackTrace();
        }
    }
    
    public void log(String message) {
        String timestamp = LocalDateTime.now().format(
            DateTimeFormatter.ofPattern("yyyy-MM-dd HH:mm:ss")
        );
        String logMessage = "[" + timestamp + "] " + message;
        System.out.println(logMessage);
        if (writer != null) {
            writer.println(logMessage);
            writer.flush();
        }
    }
}

// 使用方式
Logger.INSTANCE.log("添加商品到购物车");
```

**应用场景分析**：
- Logger：全局日志记录，确保日志输出到同一文件
- DBConnection：数据库连接池管理
- ECommerceFacade：系统外观，确保唯一入口
- EventBus：事件总线，确保事件发布订阅中心唯一
- OrderStateMachine：状态机，确保状态管理器唯一

#### 3.1.4 优化历程
最初使用饿汉式实现，后优化为枚举实现，提高了线程安全性和代码简洁性。

---

### 3.2 工厂模式 + 抽象工厂模式（Factory + Abstract Factory Pattern）

#### 3.2.1 设计意图
- **工厂模式**：定义一个创建对象的接口，让子类决定实例化哪一个类
- **抽象工厂模式**：提供一个创建一系列相关或相互依赖对象的接口

#### 3.2.2 实现方式

**简单工厂（ProductFactory）**
```java
public class ProductFactory {
    public static Product createProduct(String type, String id, String name, double price) {
        switch (type) {
            case "electronics": return new Product(id, name, price, "电子产品");
            case "clothing":    return new Product(id, name, price, "服装");
            case "food":        return new Product(id, name, price, "食品");
            case "books":       return new Product(id, name, price, "图书");
            default:            return new Product(id, name, price, "其他");
        }
    }
}
```

**抽象工厂（AbstractFactory + ECommerceFactory）**
```java
public interface AbstractFactory {
    Product createProduct(String type, String id, String name, double price);
    PromotionStrategy createStrategy(String type, Object... params);
}

public class ECommerceFactory implements AbstractFactory {
    @Override
    public Product createProduct(String type, String id, String name, double price) {
        // 创建产品逻辑
    }
    
    @Override
    public PromotionStrategy createStrategy(String type, Object... params) {
        switch (type) {
            case "COUPON":         return new CouponStrategy();
            case "FULL_REDUCTION": return new FullReductionStrategy(...);
            case "VIP":            return new VipDiscountStrategy(...);
            // ...
        }
    }
}
```

#### 3.2.3 应用场景
- **CartService**：使用ECommerceFactory创建商品
- **CheckoutFrame**：使用StrategyFactory创建促销策略
- **StrategyContext**：通过工厂自动创建策略

#### 3.2.4 设计优势
1. 解耦：客户端不需要知道具体产品类的类名
2. 扩展性：新增产品类型只需修改工厂类
3. 统一管理：抽象工厂统一管理相关对象的创建

## 四、结构型模式详解

### 4.1 适配器模式（Adapter Pattern）

#### 4.1.1 设计意图
将一个类的接口转换成客户希望的另一个接口，使原本不兼容的类可以一起工作。

#### 4.1.2 实现方式
本项目采用**对象适配器** + **默认适配器**模式：

**默认适配器（AbstractPaymentAdapter）**
```java
public abstract class AbstractPaymentAdapter implements PaymentAdapter {
    @Override
    public boolean pay(Order order) { return false; }
    
    @Override
    public String getPaymentMethod() { return "默认支付方式"; }
    
    @Override
    public boolean refund(Order order) { return false; }
    
    @Override
    public String getPaymentDescription() { return "默认支付方式描述"; }
    
    @Override
    public double getDiscount() { return 0.0; }
}
```

**具体适配器（AlipayAdapter）**
```java
public class AlipayAdapter extends AbstractPaymentAdapter {
    @Override
    public boolean pay(Order order) {
        Logger.INSTANCE.log("支付宝支付: " + order.getFinalAmount());
        return true;
    }
    
    @Override
    public String getPaymentMethod() { return "支付宝"; }
    
    @Override
    public double getDiscount() { return 0.05; } // 5%折扣
}
```

#### 4.1.3 应用场景
- **PaymentService**：统一管理多种支付方式
- 支持支付宝、微信支付、信用卡、银行卡等多种支付方式

#### 4.1.4 设计优势
1. 默认适配器减少代码冗余
2. 新增支付方式只需继承AbstractPaymentAdapter
3. 统一的支付接口，便于扩展

---

### 4.2 装饰器模式（Decorator Pattern）

#### 4.2.1 设计意图
动态地给一个对象添加一些额外的职责，就增加功能来说，装饰器模式比生成子类更为灵活。

#### 4.2.2 实现方式

**商品接口**
```java
public interface ProductInterface {
    String getId();
    String getName();
    double getPrice();
}
```

**装饰器抽象类**
```java
public abstract class ProductDecorator implements ProductInterface {
    protected ProductInterface decoratedProduct;
    
    public ProductDecorator(ProductInterface decoratedProduct) {
        this.decoratedProduct = decoratedProduct;
    }
    
    @Override
    public String getId() { return decoratedProduct.getId(); }
}
```

**折扣装饰器**
```java
public class DiscountDecorator extends ProductDecorator {
    private double discountRate;
    
    public DiscountDecorator(ProductInterface decoratedProduct, double discountRate) {
        super(decoratedProduct);
        this.discountRate = discountRate;
    }
    
    @Override
    public double getPrice() {
        return decoratedProduct.getPrice() * (1 - discountRate);
    }
    
    @Override
    public String getName() {
        return decoratedProduct.getName() + " (折扣: " + (int)(discountRate * 100) + "%)";
    }
}
```

#### 4.2.3 应用场景
- **CheckoutFrame**：结算时动态装饰商品价格
- 支持多层装饰：折扣 + 促销标签

#### 4.2.4 设计优势
1. 组合优于继承
2. 动态添加职责
3. 可以叠加多个装饰器

---

### 4.3 外观模式（Facade Pattern）

#### 4.3.1 设计意图
为子系统中的一组接口提供一个一致的界面，外观模式定义了一个高层接口，这个接口使得这一子系统更加容易使用。

#### 4.3.2 实现方式

**外观类（枚举单例）**
```java
public enum ECommerceFacade {
    INSTANCE;
    
    private CartService cartService;
    private OrderService orderService;
    private PaymentService paymentService;
    // ... 其他服务
    
    private ECommerceFacade() {
        this.cartService = new CartService();
        this.orderService = new OrderService();
        this.paymentService = new PaymentService();
        // ... 初始化其他服务
        Logger.INSTANCE.log("初始化电商系统外观");
    }
    
    // 购物车操作
    public void addProduct(String type, String id, String name, double price, int quantity) {
        cartService.addProduct(type, id, name, price, quantity);
    }
    
    // 订单操作
    public Order createOrder(Cart cart) {
        return orderService.createOrder(cart);
    }
    
    // 服务访问方法
    public CartService getCartService() { return cartService; }
    public OrderService getOrderService() { return orderService; }
    // ...
}
```

#### 4.3.3 应用场景
- **所有UI层**：通过ECommerceFacade.INSTANCE获取服务引用
- 统一的服务入口，降低UI层与Service层的耦合

#### 4.3.4 设计优势
1. 简化接口：客户端只需与外观交互
2. 解耦：UI层不直接依赖具体Service实现
3. 与单例模式结合：确保唯一实例

## 五、行为型模式详解

### 5.1 策略模式（Strategy Pattern）

#### 5.1.1 设计意图
定义一系列算法，把它们一个个封装起来，并且使它们可相互替换。策略模式让算法独立于使用它的客户端而变化。

#### 5.1.2 实现方式

**策略接口**
```java
public interface PromotionStrategy {
    double calculateDiscount(Order order);
}
```

**策略上下文（与工厂模式结合）**
```java
public class StrategyContext {
    private PromotionStrategy strategy;
    private AbstractFactory factory;
    
    public StrategyContext() {
        this.factory = new ECommerceFactory();
    }
    
    public void setStrategy(PromotionStrategy strategy) {
        this.strategy = strategy;
    }
    
    public void selectStrategy(String type, Object... params) {
        this.strategy = factory.createStrategy(type, params);
    }
    
    public double executeStrategy(Order order) {
        if (strategy != null) {
            return strategy.calculateDiscount(order);
        }
        return 0;
    }
}
```

**具体策略**
```java
public class CouponStrategy implements PromotionStrategy {
    @Override
    public double calculateDiscount(Order order) {
        Coupon coupon = order.getSelectedCoupon();
        if (coupon != null) {
            return coupon.getAmount();
        }
        return 0;
    }
}

public class FullReductionStrategy implements PromotionStrategy {
    private double threshold;
    private double reduction;
    
    public FullReductionStrategy(double threshold, double reduction) {
        this.threshold = threshold;
        this.reduction = reduction;
    }
    
    @Override
    public double calculateDiscount(Order order) {
        if (order.getOriginalAmount() >= threshold) {
            return reduction;
        }
        return 0;
    }
}
```

#### 5.1.3 应用场景
- **CheckoutFrame**：计算不同类型的折扣
- **Handler**：通过StrategyContext执行策略

#### 5.1.4 设计优势
1. 算法可独立变化
2. 与工厂模式结合，灵活选择策略
3. 易于扩展新的促销策略

### 5.2 职责链模式（Chain of Responsibility Pattern）

#### 5.2.1 设计意图
使多个对象都有机会处理请求，从而避免请求的发送者和接收者之间的耦合关系。将这些对象连成一条链，并沿着这条链传递该请求。

#### 5.2.2 实现方式

**处理器抽象类（与策略模式结合）**
```java
public abstract class Handler {
    protected Handler next;
    protected StrategyContext strategyContext;
    
    public Handler(StrategyContext strategyContext) {
        this.strategyContext = strategyContext;
    }
    
    public Handler(PromotionStrategy strategy) {
        this.strategyContext = new StrategyContext();
        this.strategyContext.setStrategy(strategy);
    }
    
    public void setNext(Handler next) {
        this.next = next;
    }
    
    public abstract void handle(Order order);
}
```

**具体处理器**
```java
public class CouponHandler extends Handler {
    public CouponHandler(StrategyContext strategyContext) {
        super(strategyContext);
    }
    
    @Override
    public void handle(Order order) {
        double discount = strategyContext.executeStrategy(order);
        order.setCouponDiscount(discount);
        if (next != null) {
            next.handle(order);
        }
    }
}
```

**职责链构建**
```java
Handler couponHandler = new CouponHandler(couponContext);
Handler fullReductionHandler = new FullReductionHandler(fullReductionContext);
Handler vipHandler = new VipHandler(vipContext);

couponHandler.setNext(fullReductionHandler);
fullReductionHandler.setNext(vipHandler);

couponHandler.handle(order);
```

#### 5.2.3 应用场景
- **CheckoutFrame.calculateDiscounts()**：依次计算优惠券、满减、VIP折扣
- 可视化展示职责链流转过程

#### 5.2.4 设计优势
1. 请求发送者和接收者解耦
2. 与策略模式结合，每个节点使用不同策略
3. 动态调整链的顺序和节点

### 5.3 观察者模式（Observer Pattern）

#### 5.3.1 设计意图
定义对象间的一种一对多的依赖关系，当一个对象的状态发生改变时，所有依赖于它的对象都得到通知并被自动更新。

#### 5.3.2 实现方式

**传统观察者模式**
```java
public interface Observer {
    void update();
}

public interface Subject {
    void registerObserver(Observer observer);
    void removeObserver(Observer observer);
    void notifyObservers();
}
```

**事件总线（发布-订阅模式）**
```java
public class EventBus {
    private static final EventBus instance = new EventBus();
    private Map<String, List<Observer>> eventObservers;
    
    private EventBus() {
        eventObservers = new HashMap<>();
    }
    
    public static EventBus getInstance() {
        return instance;
    }
    
    public void registerObserver(String eventType, Observer observer) {
        if (!eventObservers.containsKey(eventType)) {
            eventObservers.put(eventType, new ArrayList<>());
        }
        eventObservers.get(eventType).add(observer);
    }
    
    public void publishEvent(String eventType) {
        if (eventObservers.containsKey(eventType)) {
            for (Observer observer : eventObservers.get(eventType)) {
                observer.update();
            }
        }
    }
}
```

**被观察者（Cart）**
```java
public class Cart implements Subject {
    private List<Observer> observers;
    private EventBus eventBus;
    
    public Cart() {
        observers = new ArrayList<>();
        eventBus = EventBus.getInstance();
    }
    
    public void addItem(ProductInterface product, int quantity) {
        // 添加商品逻辑
        notifyObservers();           // 传统方式
        publishCartChanged();        // EventBus方式
    }
    
    private void publishCartChanged() {
        eventBus.publishEvent("CART_CHANGED");
    }
}
```

#### 5.3.3 应用场景
- **Cart**：购物车状态变更时发布事件
- **CartFrame**：订阅购物车变更事件，更新UI

#### 5.3.4 设计优势
1. 传统观察者与EventBus并存，增强灵活性
2. 按事件类型管理观察者
3. 解耦事件发布者和订阅者

### 5.4 命令模式（Command Pattern）

#### 5.4.1 设计意图
将一个请求封装为一个对象，从而使你可用不同的请求对客户进行参数化；对请求排队或记录请求日志，以及支持可撤销的操作。

#### 5.4.2 实现方式

**命令接口**
```java
public interface Command {
    void execute();
    void undo();
}
```

**命令管理器（支持批处理和事务）**
```java
public class CommandManager {
    private Stack<Command> commandStack;
    private List<Command> commandQueue;
    
    public void executeCommand(Command command) {
        command.execute();
        commandStack.push(command);
    }
    
    public void addCommand(Command command) {
        commandQueue.add(command);
    }
    
    public void executeBatch() {
        for (Command command : commandQueue) {
            command.execute();
            commandStack.push(command);
        }
        commandQueue.clear();
    }
    
    public void executeTransaction() {
        List<Command> executedCommands = new ArrayList<>();
        try {
            for (Command command : commandQueue) {
                command.execute();
                executedCommands.add(command);
                commandStack.push(command);
            }
            commandQueue.clear();
        } catch (Exception e) {
            // 发生异常，撤销已执行的命令
            for (Command command : executedCommands) {
                command.undo();
            }
        }
    }
    
    public void undo() {
        if (!commandStack.isEmpty()) {
            Command command = commandStack.pop();
            command.undo();
        }
    }
}
```

**具体命令**
```java
public class AddProductCommand implements Command {
    private CartService cartService;
    private String type, id, name;
    private double price;
    private int quantity;
    
    @Override
    public void execute() {
        cartService.addProduct(type, id, name, price, quantity);
    }
    
    @Override
    public void undo() {
        cartService.removeProduct(id);
    }
}
```

#### 5.4.3 应用场景
- **CartFrame**：所有购物车操作通过命令执行
- 支持撤销、批处理、事务

#### 5.4.4 设计优势
1. 操作可撤销
2. 支持批处理和事务
3. 命令队列管理

### 5.5 模板方法模式（Template Method Pattern）

#### 5.5.1 设计意图
定义一个操作中的算法的骨架，而将一些步骤延迟到子类中。模板方法使得子类可以不改变一个算法的结构即可重定义该算法的某些特定步骤。

#### 5.5.2 实现方式

**模板类（带钩子方法）**
```java
public abstract class OrderProcessTemplate {
    public final void processOrder(Order order) {
        validateOrder(order);
        calculatePrice(order);
        if (needProcessPayment()) {  // 钩子方法
            processPayment(order);
        }
        updateInventory(order);
        generateOrder(order);
        if (needSendNotification()) {  // 钩子方法
            sendNotification(order);
        }
    }
    
    protected abstract void validateOrder(Order order);
    protected abstract void calculatePrice(Order order);
    protected abstract void processPayment(Order order);
    protected abstract void updateInventory(Order order);
    protected abstract void generateOrder(Order order);
    protected abstract void sendNotification(Order order);
    
    // 钩子方法
    protected boolean needProcessPayment() { return true; }
    protected boolean needSendNotification() { return true; }
}
```

**具体实现**
```java
public class VipOrderProcessor extends OrderProcessTemplate {
    @Override
    protected void calculatePrice(Order order) {
        // VIP专属价格计算
    }
    
    @Override
    protected boolean needSendNotification() {
        return false;  // VIP订单不发送通知
    }
}
```

#### 5.5.3 应用场景
- **OrderService.submitOrder()**：根据订单类型选择不同处理器

#### 5.5.4 设计优势
1. 算法骨架固定，细节可变
2. 钩子方法提供灵活性
3. 代码复用

### 5.6 状态模式（State Pattern）

#### 5.6.1 设计意图
允许一个对象在其内部状态改变时改变它的行为，对象看起来似乎修改了它的类。

#### 5.6.2 实现方式

**状态接口**
```java
public interface OrderState extends Serializable {
    void pay(Order order);
    void ship(Order order);
    void complete(Order order);
    void cancel(Order order);
    String getStateName();
}
```

**状态机（单例）**
```java
public class OrderStateMachine {
    private static final OrderStateMachine instance = new OrderStateMachine();
    
    private final OrderState pendingPaymentState = new PendingPaymentState();
    private final OrderState paidState = new PaidState();
    private final OrderState shippedState = new ShippedState();
    private final OrderState completedState = new CompletedState();
    private final OrderState cancelledState = new CancelledState();
    
    public void initializeState(Order order) {
        order.setState(pendingPaymentState);
    }
    
    public void processPayment(Order order) {
        order.getState().pay(order);
    }
    
    public void processShipment(Order order) {
        order.getState().ship(order);
    }
    // ...
}
```

**具体状态**
```java
public class PendingPaymentState implements OrderState {
    @Override
    public void pay(Order order) {
        order.setState(OrderStateMachine.getInstance().getPaidState());
        Logger.INSTANCE.log("订单已支付");
    }
    
    @Override
    public void ship(Order order) {
        throw new IllegalStateException("待支付订单不能发货");
    }
    
    @Override
    public String getStateName() { return "待支付"; }
}
```

#### 5.6.3 应用场景
- **Order**：订单状态管理
- **OrderService**：通过状态机处理状态转换

#### 5.6.4 设计优势
1. 状态转换逻辑集中管理
2. 状态机单例，预创建状态实例
3. 状态行为封装在状态类中

## 六、设计模式协作关系

### 6.1 模式组合应用

本项目展示了多种设计模式的协作使用：

#### 6.1.1 外观模式 + 单例模式
```
ECommerceFacade（枚举单例）
    └── 聚合所有Service
        └── UI层通过INSTANCE访问
```

#### 6.1.2 职责链模式 + 策略模式 + 工厂模式
```
CheckoutFrame
    └── 创建StrategyContext
        └── 通过ECommerceFactory创建策略
            └── 注入到Handler
                └── 构建职责链
                    └── 依次处理折扣计算
```

#### 6.1.3 观察者模式 + 事件总线
```
Cart（Subject）
    ├── notifyObservers() ──→ CartFrame（Observer）
    └── EventBus.publishEvent("CART_CHANGED")
            └── EventBus通知订阅者
```

#### 6.1.4 状态模式 + 状态机
```
OrderService
    └── OrderStateMachine.getInstance()
        ├── initializeState(order)
        ├── processPayment(order)
        ├── processShipment(order)
        └── processCompletion(order)
```

#### 6.1.5 命令模式 + 命令队列
```
CartFrame
    └── CommandManager
        ├── executeCommand() ──→ 执行单个命令
        ├── executeBatch() ──→ 批处理
        ├── executeTransaction() ──→ 事务执行
        └── undo() ──→ 撤销
```

### 6.2 协作优势

1. **解耦**：各模式职责明确，降低耦合度
2. **扩展性**：新增功能只需扩展对应模式
3. **可维护性**：代码结构清晰，易于理解
4. **灵活性**：模式组合使用，适应复杂场景

## 七、总结与展望

### 7.1 项目成果

1. **11种设计模式深度应用**：每种模式都真正融入业务流程
2. **模式协作**：展示了多种模式的组合使用
3. **完整业务流程**：购物车、订单、会员、物流、评价等完整实现
4. **代码质量**：模块化设计，易于理解和维护

### 7.2 设计原则遵循

- **单一职责原则（SRP）**：每个类只负责一个职责
- **开闭原则（OCP）**：对扩展开放，对修改关闭
- **里氏替换原则（LSP）**：子类可以替换父类
- **接口隔离原则（ISP）**：接口最小化
- **依赖倒置原则（DIP）**：依赖抽象而非具体实现

### 7.3 后续优化方向

1. 引入依赖注入框架（如Spring）
2. 添加单元测试覆盖
3. 性能优化和缓存机制
4. 引入更多设计模式（如建造者模式、原型模式等）
